# 4. Hardware demo: run the new API on NQCH

## What was built

Elis scanned the server to find out the current configuration in terms of dependencies that Paul was using to make Arthur's provider work. This was a huge bottleneck since it was not disclosed nor documented anywhere and in fact Sergi had scheduled a "sit down" session with Paul just for this purpose. Instead, after figuring this out independently, Elis prepared an **isolated server environment** containing Paul's QM/QuAM setup and an editable checkout of the `eo-switch-native-execution` Qibo branch, leaving Paul's environment untouched. We used Arthur's underlying **Qiskit QM backend**. The working path is:

```java
Qibo IfElse/Switch circuit
  → Qibo OpenQASM 3 export → Qiskit (+Qiskit translation to physical layout)
  → Arthur's Qiskit QM backend → OpenQASM 3 → qm-qasm → QUA → QM hardware

```

The scripts load `sinq20` QuAM state, wiring, and macros; verify placement and control flow; optionally compile offline to inspect the QUA branches; then call `qm_backend.run()`. The `qm-qasm` update supplied the missing two-bit-register comparison needed by the repetition-code `Switch`. The completed notebook adds SSH/Slurm helpers that submit a job when the user runs its cell, wait for that job, collect logs and counts, and plot the results. Notice that at the moment, when executing one of the notebook cells to launch a slurm job, the code that is executing the circuit is the script living in the server which has a copy of that circuit, it is not the circuit you type in the notebook that gets executed against nqch but its pre-prepared hardware version sitting in the cluster.

| Demo | Explicit physical qubits | Saved notebook run, 1,000 shots |
| --- | --- | --- |
| Fast reset (`IfElse`) | `q15` | Job `65835` completed; 901 final zero outcomes. |
| T-gate teleportation (`IfElse`) | `q15`, `q19` | Job `65836` completed; final `P(1)=0.160` (ideal about 0.146). |
| Repetition code (`Switch`) | wires 0–4 → `q5`, `q10`, `q9`, `q15`, `q19` | Job `65837` completed; 653 final `000` outcomes. |

The repetition circuit uses only CZ edges `q5–q10`, `q9–q10`, `q10–q15`, and `q15–q19`; a `q10–q9` SWAP moves the middle data state between parity checks.

## Why it mattered

This connected the readable Qibo API to real feedback execution without waiting for the direct provider paths to gain native knowledge of `IfElse` and `Switch`.
