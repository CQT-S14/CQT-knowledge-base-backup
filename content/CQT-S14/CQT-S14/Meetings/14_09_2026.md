### Current state

- **Environment folder for hardware dependencies/drivers (**`qm-py312-131`**):**   
  Nearly done. It holds the Quantum Machines dependencies (mostly from the official QM Python package `qm-qua pypi`) plus drivers for the OPX1000 instrument, which are already installed. Drivers for the second instrument, the QDAC, may not be needed because the instrument is allegedly always On. Having to install its drivers would force it to be wired into `qibola`, which Paul wants to avoid if possible.
- **Calibration status:** QM left the calibration incomplete.
- The 5-qubit chip couldn't be calibrated (faulty chip, not QM's fault).
- The 20-qubit chip has single-qubit calibration done, but most two-qubit pairs are still uncalibrated. This is Paul's current top priority.
- **Prototype backend:** Rather than extending `qibolab` backend directly, Paul built a separate, minimal Quantum Machines backend to prototype the `calibration → parameters` pipeline. It's structurally working (JSON formatting is correct) but produces incorrect values — there's a mapping bug between what's extracted from the QM UI and what lands in the parameters JSON. This can't be debugged until the two-qubit calibration is actually finished.
- **Parallel track:** Arthur Strauss is expected to build on or replicate this QM-backend for a more production-grade version that also supports error correction. This dedicated backend is expected to be relevant for advanced users only, and independent of the regular-user `qibolab`.
- **Regular users right now:** Can technically run jobs with `qibolab` pointing at the `qm-py312-131` environment, but the calibration .json parameters currently loaded are leftover Keysight calibration values, not Quantum Machines ones (since the 20q chip is still not fully calibrated). Any run right now would look functional but be scientifically invalid.

### What still has to happen before regular users are fully back on QM hardware

1. Finish two-qubit calibration on the 20-qubit chip.
2. Debug the parameter-mapping bug in the prototype backend.
3. Port that corrected parameter-passing logic into `qibolab` itself.
4. Point regular users' scripts at the QM folder instead of Keysight, once `qibolab` is actually loading QM-derived .json calibration parameters.
